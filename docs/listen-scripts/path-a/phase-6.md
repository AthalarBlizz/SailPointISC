Cold open. Not every problem is write a script against the A P I. Conversational developers know the extension-point menu and pick the lightest tool that fits.

Outcome: name transforms, rules, workflows, SaaS Connectivity, customizers, and external integrations — and choose correctly for a use case.

Transforms are JSON config for attribute calculate and map on aggregate or provision. Prefer them over rules when possible. Deterministic string normalize — lowercase an H R email into an identity attribute — is transform vocabulary.

Rules are BeanShell for logic transforms cannot express. Expect SailPoint review and install constraints. Don’t reach for a rule because it feels more powerful — reach for it when transforms truly cannot express the logic.

Workflows are low-code plus H T T P actions for event-driven process automation. Scan those H T T P actions for legacy yearly paths and slash latest. Use Workflow Analyzer mindset: find them, rewrite to per-service paths, verify before Q one twenty twenty-nine.

SaaS Connectivity is TypeScript custom connectors in SailPoint cloud — target reachable from cloud, with spcx — the SaaS Connectivity local debugger — for local debug. Connector customizers are TypeScript hooks to tweak out-of-the-box connector input and output — more flexible than classic rules for many SaaS sources. Contrast with on-prem: systems that need a virtual appliance — V A — or classic connectivity stay on that path; do not force a SaaS connector when the target is not cloud-reachable.

External integrations remain this curriculum’s core: any language via A P I for I T D R, H R, S I E M, ticketing — Personal Access Token plus per-service call sheet.

Decision tree in words: attribute mapping only — transform. Event side effects over H T T P — workflow. Need a new Source to aggregate and provision — SaaS Connectivity. Tweak an out-of-the-box connector’s I O — customizer. Complex BeanShell only — rule. Otherwise external A P I script.

Say this: prefer transforms before rules. Prefer workflows for event side effects. Prefer connectors when you need a Source. Prefer external A P I when another system owns the trigger. A loopback connector is appropriate when you want I S C to manage I S C objects as if they were a target system — SaaS Connectivity plus the A P I S D K inside the connector.

Watch-outs. Cloud rule for a lowercase. Workflow H T T P still on slash v two zero two five with no migration plan. Building a nightly invent-accounts script instead of a connector for a net-new SaaS app. Skipping Workflow Analyzer while declaring migration done.

When you’re back at the screen, take the micro-check — lowercase H R email on aggregation is a transform. Then drill: transform or rule, risk of workflow H T T P on yearly paths, and when a loopback connector is appropriate.
