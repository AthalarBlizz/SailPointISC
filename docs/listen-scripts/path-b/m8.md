Module eight is the TypeScript software development kit — S D K — story for Identity Security Cloud. Cold open: if your team lives in Node, this is how you call the platform without hand-rolling every path — and without confusing three different TypeScript packages that all say SailPoint on the box.

Outcomes for this lesson: scaffold Configuration with Accounts A P I and Identities A P I, call list methods with a V one suffix, tell A P I S D K apart from Connector S D K and customizers, and describe the one-point-x to two-point-oh migration rewrite.

There are three TypeScript surfaces. First: sailpoint-api-client — the A P I S D K. It talks to I S C REST from Node or TypeScript services. Second: at-sailpoint slash connector-sdk plus spcx — the SaaS Connectivity local debugger — that is SaaS Connectivity, for custom cloud connectors. Third: the customizer framework — TypeScript hooks that mutate before or after connector operations. Same language family, three different jobs.

In two point x, you import resource A P Is without year namespaces. You get AccountsApi and IdentitiesApi, not Accounts V two zero two five Api. Method names carry the version: list Accounts V one, list Identities V one, and so on. That mirrors per-service paths like slash accounts slash v one.

Configuration still reads SAIL base URL, SAIL client I D, and SAIL client secret from the environment. Prefer Personal Access Token auth for scripts. Reuse one token per run. Do not mint a fresh token on every call.

Command line interface — C L I — bootstrap is the team standard: sail sdk init typescript, then sail sdk init config. Pin the dependency major to two point x. When SailPoint ships a new service major, review the changelog — do not assume every method stays on V one forever.

Say this in design review: a nightly compliance job uses the A P I S D K. A brand-new SaaS H R app with no out-of-the-box connector needs the Connector S D K. Do not put A P I client code inside a connector package and call it done.

Worked example: resolve Jennifer by alias with list Identities V one and a filter, take the identity I D, then list Accounts V one filtered by that identity I D. Always resolve by name or alias at runtime — never hardcode tenant GUIDs from sandbox into prod.

Migration: run the official migration script. It rewrites year-named A P Is to resource classes plus V one or V two suffixes. Review V two outliers by hand — access-request-config and similar config endpoints are not blindly V one. For entitlements, confirm slash entitlements slash v one in Open A P I and check the migration table before assuming V two.

Failure modes: importing Accounts V two zero two five Api in new code after a two point x upgrade; using the A P I S D K where connector-sdk is required; committing SAIL client secret in a dot env to make continuous integration “work.”
