Module fifteen is SaaS Connectivity — custom TypeScript connectors. Cold open: if Identity Security Cloud must aggregate accounts and entitlements and provision as a Source, you need a connector. If you only call I S C when I T D R fires, you need an external integration — not a connector.

Outcomes: explain when out-of-the-box is insufficient and SaaS Connectivity is justified; sketch command handlers for test connection, account list and read, entitlements, and provision; use spcx — the SaaS Connectivity local debugger — for local debug and know the loopback pattern’s risks.

Package story: at-sailpoint slash connector-sdk plus spcx. This is not sailpoint-api-client. Confusing those two TypeScript surfaces is the module eight failure mode all over again. Connectors speak the Source contract; A P I clients speak platform REST.

Command lifecycle order of proof: test connection first, then account list, then read and entitlement operations, then create, update, and disable. Prove aggregation before provisioning. A connector that can create but cannot list is not enterprise-ready.

When to build: a SaaS app with no out-of-the-box connector, reachable from SailPoint cloud. Loopback — I S C managing I S C-shaped resources through Source semantics — is powerful and easy to get wrong; require an architecture decision record and rate-limit design.

When not: on-prem-only systems that need virtual appliance or classic connectivity patterns; a simple nightly A P I job that does not need source aggregation semantics — that is module four, eight, or nine, not a connector.

Say this: for a new SaaS H R app that should be an I S C Source, we use Connector S D K. For I T D R disable, we use REST or A P I S D K against lifecycle. Building a connector to open a ticket is usually a workflow H T T P action in disguise.

Delivery craft: design account and entitlement schema before code; attach spcx test evidence to the pull request; map provisioning operations to I S C plan ops; name an owner team for connector version upgrades; rotate long-lived SaaS secrets in source config.

Failure modes: connector for one-way ticket create that should be workflow; blocking aggregation on chatty unpaginated remote A P Is; no rotation plan for SaaS secrets; skipping list and read before Std Account Create.

When you’re back at the screen: narrate the command order test, list, read, entitlements, provision — then answer A P I S D K versus Connector S D K for a new SaaS H R Source with no out-of-the-box option.
