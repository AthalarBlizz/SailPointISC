Cold open. Module five is filters, Search, PATCH, and bulk patterns. Picking Search for an I T D R disable can hit index lag and miss the identity you must act on now. Picking list plus deep offset for a million-row analytics dump burns rate budget and time. Choose the tool by workload.

Outcomes for this module. You can write standard collection filters with equals, starts with, contains, in, and, and correct quoting. You can choose list filters versus Search with search-after for the right workload. And you can apply JSON Patch with the correct content type and respectful bulk and pagination.

Teach — list filters. Collection list A P Is take a filters query for simpler predicates. Examples you should be able to say: alias eq, then the quoted value. Name starts with a quoted prefix. First name starts with and status equals ACTIVE. Created greater than an I S O timestamp. Name in a quoted list. Identity I D equals a quoted GUID. Unquoted strings are a classic four hundred.

Teach — Search versus list. List plus filters gives near real-time resource collections with limit and offset pagination — prefer this for I T D R and simple alias lookups when the collection A P I supports them. Search uses an index query language; page with search-after after large limits — great for wide reporting and reconciliation, but accept possible index lag. Search is not a substitute for an authoritative identity GET when you already have the I D.

Teach — PATCH versus PUT. Partial updates use JSON Patch operations — add, replace, remove — with content type application slash json-patch plus json. PUT of an entire object from a stale GET loses concurrent updates. Prefer PATCH when you mean to change specific fields only.

Teach — bulk and rate respect. Batch within rate limits; prefer documented server bulk endpoints when they exist. Verify a sample of results after bulk jobs. Reuse one token; retry four twenty-nine with jitter. Deep offset pagination on huge sets has a cost — measure it or switch to search-after for analytics-scale reads.

Example — say this for an identity lookup. For alias Jennifer dot Thomas, use list identities with filters alias eq, quote Jennifer dot Thomas, against slash identities slash v one. Do not open Search first for a single known alias when the list filter works.

Example — say this for a reporting job. Broad, index-oriented queries and large result sets use Search and search-after. Document that results may lag the live identity store. For real-time disable when you already have the identity I D, skip search theater — get and mutate directly.

Failure modes. Unquoted strings in filters producing four hundreds. Using Search on the I T D R path that needs an authoritative identity. PUT entire objects from stale GETs. Offset walking millions of rows without measuring cost. Wrong PATCH content type so the server rejects or misreads the body.

Failure modes, continued. Replacing governed access changes with blind PATCH of assignments. Bulk jobs with no dry-run or progress metrics. Ignoring four twenty-nine and hammering the tenant. Treating Search hit counts as proof the identity does not exist.
