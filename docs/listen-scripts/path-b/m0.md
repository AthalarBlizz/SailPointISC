# Module — Platform model

> **Unit ID:** `m0`  
> **Path:** B · Implementation  
> **Source of truth for Listen mode.** Edit paragraphs below; blank lines separate spoken utterances.

---

Cold open. Module zero is the platform model. If you confuse an identity with an account, you will pick the wrong A P I, break provisioning assumptions, and sound junior in a design review. Every Identity Security Cloud — I S C — integration mutates or reads a small set of objects. Learn the nouns first.

Outcomes for this module. By the end you can draw the identity to account to entitlement to access profile to role chain from memory. You can explain where lifecycle state sits relative to provisioning and sources. And you can decide whether a change belongs in the U I, an A P I or S D K script, or a connector story.

Teach — what I S C governs. An identity is the person or machine I S C governs. An account is that identity’s record on a specific source — Active Directory, Salesforce, a custom app. One identity usually has many accounts. Sources are the connected systems I S C aggregates from and provisions to.

Teach — access composition. Entitlements are permissions or groups on a source. Access profiles bundle entitlements into reusable packages. Roles sit higher — business-shaped access that often groups access profiles. When someone says “give them finance access,” they almost always mean a role or profile, not a raw entitlement on one account.

Teach — lifecycle and the identity profile. Lifecycle states like Active, Leave of Absence, or Terminated live on the identity profile for a population. Those states drive joiner, mover, and leaver provisioning downstream to managed sources. The identity profile also owns mapping and transforms. Lifecycle is the lever; accounts on sources are the effect.

Teach — object resolution. Almost every I S C object is a tenant-specific GUID. Resolve by name at runtime — filter identities by alias, list lifecycle states on the profile and match Terminated by name, look up sources and roles by name. Never hardcode sandbox I Ds into a production script. Paths for new work look like slash identities slash v one, slash accounts slash v one, slash sources slash v one.

Teach — who owns the change. H R and authoritative sources feed aggregation and transforms — that is batch truth on a schedule. Security and identity threat detection and response — I T D R — need A P I lifecycle or account disable in seconds. Business access goes through access request and approvals. A net-new SaaS app needs a connector story, not a nightly invent-accounts script.

Example — say this in design review. Emergency disable sets the Terminated lifecycle state, resolved by name on the identity profile, so I S C cascades disables to managed sources. Peer clone submits access requests; it does not bypass approvals or assign entitlements directly. Aggregation lag is not a substitute for an A P I-driven leaver when security needs action now.

Example — U I versus code. Configure in product when an admin can own the change and no external system must trigger it. Reach for the A P I or S D K when ServiceNow, a SIEM, or an automation must act, or when the U I cannot express the workflow. Extension points that are not “call the public A P I from a script” include transforms, rules, workflows, SaaS Connectivity connectors, and connector customizers.

Failure modes. Treating account disable on one source as “identity offboarded” without a lifecycle change. Hardcoding lifecycle state or role GUIDs from sandbox into prod. Building per-app disable loops for managed sources that already provision from lifecycle. Confusing Search index lag with list-filter freshness when I T D R needs the authoritative identity right now.

Failure modes, continued. Using access request to remove access for a compromised leaver — that is the wrong governance path. Inventing accounts overnight instead of onboarding a source. Assuming one entitlement equals one business role. Skipping before and after verification after any mutation.

Screen close. Module zero is fluency of the object graph and ownership. Identity, account, entitlement, access profile, role, lifecycle, source — resolve by name, pick the right owner of change, and never confuse batch H R truth with security-speed A P I action. Next foundation module is authentication and scopes.
