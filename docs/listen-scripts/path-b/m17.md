Module seventeen is architecture patterns for Identity Security Cloud integrations. Cold open: without a shared picture, teams reinvent point-to-point scripts — ITDR calling Search ad hoc, H R patching attributes a connector already owns, and peer clone bypassing approvals.

Outcomes: draw reference architectures for ITDR disable, joiner-mover-leaver bridges, and peer provisioners; separate ISC domain language from upstream H R and ITSM models with an anti-corruption layer; choose sync request-response versus queue or workflow handoff deliberately.

Reference skeletons in words. ITDR disable: SOAR to REST or software development kit, resolve identity, set Terminated by name, verify. Compliance bridge: scheduler to rules engine to lifecycle or access requests with dry-run. Peer provisioner: compare peer access, submit access requests, keep approvals. Source of truth: connector aggregate, transforms, identity, provision out.

Anti-corruption: map external employee status enums to ISC lifecycle names explicitly. H R “inactive” is not automatically Terminated. Leaking upstream enums straight into lifecycle A P Is causes silent wrong transitions across tenants.

Idempotency: key on identity I D plus desired state so retries are safe. Async truth: an H T T P two-xx on set lifecycle does not mean every account is already disabled — design verification windows and service level objectives for lag.

Ownership boundaries: H R and authoritative sources own aggregation truth. Security owns emergency lifecycle via A P I. Business access goes through access request governance. Dual writers on the same attributes — H R aggregate plus A P I patch — fight each other in production.

Say this for peer provisioner: we submit access requests so governance, separation of duties, and audit still apply. We do not grant entitlements directly to skip approvals. We do not hardcode role GUIDs from sandbox into prod.

Architecture decision record minimum for July two thousand twenty-six: auth with Personal Access Token per integration in a vault and least-privilege scopes; versioning pinned to slash service slash v N only with S D K two point x; runtime language and S D K versus REST caller; dry-run, verify GET, and observability; migration deadline awareness for Q two twenty twenty-eight and Q one twenty twenty-nine.

When this module applies: solution architecture kickoff and multi-system programs. When it does not: single filter syntax questions or one-off Postman exploration — those are earlier modules.

Failure modes: point-to-point scripts with no owner or S L O; leaking H R enums into lifecycle A P Is; dual writers fighting; peer clone that bypasses governance.
