Cold open. Module seven is access requests, roles, and certifications. Automation is a requester, not a backdoor. Prefer slash access-requests slash v one for create and status patterns. Approvals, segregation of duties, and audit still apply — peer clone that assigns entitlements directly is a governance failure dressed as productivity.

Outcomes for this module. You can submit access requests for roles, access profiles, or entitlements with approvals intact. You can design peer clone as dry-run then request, not direct grant. And you know where certification and request-config A P Is sit — including v two outliers on the migration table.

Teach — access request posture. Joiner role packages, peer clone, and training enrollment should create access requests, then poll or webhook for status. Cancel and close paths need error handling. Do not treat “request submitted” as “access granted” in success metrics — pending approval S L As still matter.

Teach — peer clone pattern. Collect the peer’s roles and entitlements. Produce a dry-run artifact for manager or audit review. Submit access requests for the approved set. Never copy access by raw entitlement assignment A P Is unless written policy explicitly allows it. Resolve role and access profile I Ds by name at runtime — sandbox GUIDs fail in prod.

Teach — certifications literacy. Certification campaigns review and revoke access on a schedule. Integrations usually report, kick off, or sync decisions — they do not replace I T D R emergency disable. Do not confuse a campaign revoke with setting Terminated lifecycle. Read scopes carefully; campaign A P Is are easy to over-privilege.

Teach — version foot-guns. Prefer slash access-requests slash v one for common create and status flows. Some access-request-config and entitlements paths map to v two, not v one — verify in the official migration table. Leaving request-config calls on legacy yearly paths is unfinished migration hiding in admin tooling.

Example — say this when someone asks why peer clone cannot just grant. Because approvals, segregation of duties, and audit are the product. Direct grants bypass the business controls the access model exists to enforce. Dry-run then access request is the senior pattern.

Example — say this when choosing revoke tools. Compromised user who must lose access now is module six — lifecycle or account disable. Scheduled business review of who still needs a role is certification. Day-two business access with a manager in the loop is access request. Pick the lane; do not mash them together.

Failure modes. Direct entitlement assignment to skip approvals. Submitting requests with sandbox role GUIDs in production. Ignoring pending approval S L As in automation success dashboards. Leaving access-request-config on yearly paths. Using certification revoke language for an emergency disable runbook.

Failure modes, continued. Over-scoped certification Personal Access Tokens. No cancel or close handling when requests stall. Peer clone without a dry-run artifact. Treating request accepted as provisioned complete without status follow-up.

Screen close. Module seven: access requests preserve governance; peer clone is dry-run then request; certifications are review campaigns, not I T D R. Pin slash access-requests slash v one, check v two outliers, resolve access objects by name. That closes the A P I craft track’s governance lane — carry the same verify-after-mutate discipline into every later module.
