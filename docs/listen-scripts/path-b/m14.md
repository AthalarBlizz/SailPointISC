Module fourteen is workflows — event-driven automation and H T T P actions inside Identity Security Cloud. Cold open: workflows win for identity events that open tickets, notify channels, or chain I S C calls with approvals baked in. They lose for heavy bulk reconciliation — that is an external job plus S D K.

Outcomes: place workflows versus external S D K jobs versus transforms correctly; scan workflow H T T P actions for legacy yearly paths and slash latest; define error handling, secrets, and idempotency for those H T T P steps.

Version debt hides here. Application code may already pin slash identities slash v one while a workflow H T T P action still posts to slash v two zero two five or slash latest. Legacy yearly paths lose support tickets through Q two twenty twenty-eight and hard stop in Q one twenty twenty-nine. Treat Workflow Analyzer mindset as mandatory in migration.

H T T P action checklist spoken: pin per-service paths — no slash latest. Resolve object I Ds in earlier steps by name — including lifecycle state I Ds. Handle non-success statuses with explicit branches; do not swallow failures. Store secrets in the workflow secret store, never hardcoded in the action.

Worked example: an identity lifecycle change to Terminated triggers a workflow that opens an I T S M ticket over H T T P — pin the ticket system’s URL, use workflow secrets for auth, and branch on non-success. Do not re-post set lifecycle state for the same Terminated event — that invites a loop. If you need a revoke path, prefer an attribute or access change that submits a governed access request, not a lifecycle re-set.

Say this: workflows are event-sized units of work. A bulk CSV compliance crunch belongs in an S D K job with dry-run. Attribute normalize on aggregate belongs in a transform. Do not stuff those jobs into workflows because the UI felt convenient.

Loop hazard: a workflow mutates an identity attribute that re-triggers the same workflow. Add guards, idempotency keys, and clear ownership for failed executions. Someone must own the dead-letter pile.

Enterprise craft: Workflow Analyzer in the migration pipeline; execution monitoring and alerting; documented trigger events and side effects; CI or review gates that flag yearly path prefixes in exported workflow definitions.

Failure modes: yearly paths left in H T T P after app code migrated; infinite re-entry loops; no owner for failed runs; secrets pasted into action headers.
