Cold open. Module one is authentication, scopes, and least privilege. A failing call is diagnosable when you separate “who is this token” from “what is this token allowed to do.” Scripts and automations prefer a Personal Access Token — P A T — with the OAuth client credentials grant. Do not paste secrets into chat, tickets, or source control.

Outcomes for this module. You can implement client-credentials token acquisition and reuse with about a twelve-minute time to live. You can separate the P A T owner’s user level from OAuth scopes when debugging a four oh three. And you can specify least-privilege scopes per integration instead of defaulting to scopes all.

Teach — the token flow. Post grant type client credentials with the P A T client I D and client secret to the tenant OAuth token endpoint. Receive an access token. Send Authorization Bearer on every Identity Security Cloud — I S C — A P I call. Reuse one token for the run. Official S D Ks refresh automatically; raw REST must not mint a new token on every request.

Teach — client I D shape and rate limits. Modern P A T client I Ds are UUIDs with dashes; legacy undashed I Ds fail auth in confusing ways. Think rate limits on the order of about one hundred requests per access token per ten seconds — confirm before quoting S L As. Minting a new token per call wastes latency and loads the token endpoint; reuse one token and let the S D K refresh.

Teach — authentication versus authorization. A four oh one means the token is missing, expired, invalid, or pointed at the wrong base U R L. A four oh three means the token worked, but you are not allowed — missing scope, insufficient user level on the P A T owner, or an endpoint that needs a user context client credentials cannot supply. A four twenty-nine means back off with jitter and reuse the token you already have.

Teach — named scopes. S P colon scopes colon default is minimal. S P colon scopes colon all is everything the user level permits — not a default posture. Prefer specific scopes ending in colon read or colon manage. Required scopes live on each Open A P I operation — extract them before you write code.

Teach — scope posture by integration. Read-only reporting gets specific read scopes. An I T D R disable job needs identity lifecycle plus read, and you document blast radius. An access request bot gets request create and status — not admin bypass. A migration scanner is read-heavy with no mutate in dry-run. Name the P A T per integration and list scopes in the runbook.

Example — say this when someone rotates the secret on a four oh three. Stop. Valid token with four oh three is almost never “bad secret.” Check scopes on the P A T, the owner’s user level, and whether the endpoint requires interactive user context. Rotating first and calling it done hides the real authorization gap.

Example — operational hygiene. Store secrets in the OS keychain locally — this repo uses python-keyring — and a vault or K M S — a key management service — in production. Never commit a dot env with client secrets. Log correlation and request I Ds; never log the bearer token or client secret. Revoke the P A T when the integration identity is offboarded.

Failure modes. New token on every request — token-endpoint churn and wasted latency. Shared P A T across unrelated apps — audit and blast-radius nightmare. Assuming four oh three means bad secret. Using scopes all because “it worked in sandbox.” Leaving a personal engineer’s P A T in a production scheduler.

Failure modes, continued. Wrong base U R L producing four oh ones that look like credential failures. Ignoring user level when scopes look correct. Skipping rate-limit headers and retry with backoff. Documenting nothing about which scopes a job actually needs.

Screen close. Module one: P A T, one token per run, least privilege scopes, and a clean split between four oh one, four oh three, and four twenty-nine. Fail closed, name the credential, revoke on offboarding. Next up is the July two thousand twenty-six versioning dual world — the fluency upgrade leadership will ask you about.
