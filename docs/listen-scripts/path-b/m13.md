Module thirteen is rules — BeanShell when transforms are not enough. Cold open: rules are privileged platform code. They are reviewed, installed through SailPoint process, and operationally heavier than JSON transforms. Use them sparingly.

Outcomes: list rule use cases transforms cannot cover; explain review and install constraints at a conversational level; prefer connector customizers for SaaS source I O mutation when that path fits — you will deepen customizers in module sixteen.

Boundary table in words: string, date, and lookup mapping — prefer transform. Complex branching plus state — rule or external plus A P I. Before and after SaaS connector operations — customizer in TypeScript. Approvals plus H T T P side effects — workflow.

Rules earn their place for complex correlation rules, attribute rules beyond transform vocabulary, or legacy patterns your org already standardized on reviewed rules. They lose when a transform can say it, when you need event-driven multi-step process, or when you call arbitrary external A P Is on every aggregate without capacity planning.

Ops notes: track which identity profiles and sources depend on each rule. Avoid silent dual-maintenance with a transform on the same attribute. For new SaaS sources, evaluate customizers before inventing a classic rule. Version rules, peer review them, and document blast radius. Installation goes through SailPoint’s review and install process — not a casual git push to the tenant.

Say this in change review: default to transform. We open a rule only when the transform vocabulary cannot express the logic or platform constraints require it. We do not deploy rules like a casual git push — SailPoint process applies.

Compared with customizers: for mutating SaaS connector payloads, TypeScript before and after hooks are often more flexible and maintainable than BeanShell. Do not reach for a classic rule out of habit when a customizer is the modern fit.

Enterprise checklist voice: inventory of rules with owners; justification recorded when transform was insufficient; test plan on sandbox identities; previous version retained for rollback.

Failure modes: rule sprawl for trivial string ops; undocumented dependencies that break aggregates after cleanup; assuming rules install like ordinary application code.

When you’re back at the screen: pick one real attribute problem from your tenant, say transform or rule out loud with a one-sentence why, and if it is SaaS connector I O, note customizer as the alternative you must consider first.
