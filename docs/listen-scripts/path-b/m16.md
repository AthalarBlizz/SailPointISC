Module sixteen is connector customizers — before and after hooks in TypeScript. Cold open: when an out-of-the-box or SaaS connector is almost right, mutate the I O — do not fork the whole connector, and do not reach for BeanShell by reflex.

Outcomes: explain customizer versus full custom connector versus classic rule; identify before and after operation hooks as the extension point; plan testing so customizer bugs do not quietly corrupt provisioning.

Weight ladder again: transform is lowest — identity attribute mapping on the profile. Customizer is medium — connector I O mutation. Full connector is highest — you own protocol and schema. Rule is heavy process — use when required, not because it is familiar.

Customizers intercept SaaS connector operations. Typical jobs: sanitize attributes before account create; drop service accounts after account list; reshape fields the out-of-the-box mapping almost got right. Keep the logic pure, logged, and fixture-tested.

Say this: customizer when an existing SaaS or out-of-the-box connector is nearly correct. Full connector when you own the protocol end to end. Transform when the need is identity-profile attribute mapping only. Rule when platform constraints or logic truly demand BeanShell.

Why customizers often beat classic rules for SaaS sources: TypeScript before and after hooks on connector I O are usually more flexible and maintainable than BeanShell for those paths. Still treat them as production code — version with the source, never hot-fix only in prod.

Testing bar: contract tests with sample input plan to expected mutated output. Sandbox proof before prod attach. Rollback procedure must include detach customizer. Silent entitlement drops in an after-list hook are career-limiting events.

Enterprise checklist voice: customizer repo and continuous integration; fixture-based tests for before and after; source attachment documented; detach runbook rehearsed.

Failure modes: customizer silently dropping entitlements; logic that belongs in transforms living in customizers “because TypeScript”; no sandbox proof; customizer used as a net-new protocol implementation instead of a real connector.

When you’re back at the screen: pick customizer or full connector for a nearly-correct SaaS source that needs one field sanitized on create, write the one-sentence why, and list one fixture you would test before attach.
