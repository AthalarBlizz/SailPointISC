Cold open. Module six is identities, accounts, lifecycle, and sources — joiner, mover, leaver, and emergency disable. Hardcoding a Terminated GUID works once in sandbox and fails silently in prod. Skipping the verify GET closes the ticket while provisioning may still be in flight.

Outcomes for this module. You can resolve an identity by alias and resolve a lifecycle state by name on the identity profile. You can explain account versus identity disable and when each is appropriate. And you can account for aggregation latency versus A P I-driven action when security needs seconds, not the next H R file.

Teach — identity versus account. Identity Security Cloud — I S C — governs the identity. Accounts live on sources. Filter accounts by identity I D or by native identity plus source. Disabling one Active Directory account is not the same as offboarding the identity. Lifecycle on the identity profile drives provisioning to managed sources.

Teach — aggregation versus A P I action. Aggregation pulls truth from authoritative sources on a schedule. Do not wait for the next H R file when a compromised account must be stopped now. Prefer A P I-driven lifecycle change for emergency disable. Unmanaged or break-glass sources may need direct account disable in addition to lifecycle.

Teach — the emergency disable sequence. Get identities with filters alias eq the target on slash identities slash v one — capture before state. List lifecycle states for that identity’s profile; pick the state whose name is Terminated — never a hardcoded GUID. Post set-lifecycle-state with the resolved lifecycle state I D. Get the identity again and record after state in the run log.

Teach — path pins for new work. Prefer slash identities slash v one, slash accounts slash v one, and slash sources slash v one. Resolve source names when you must target a specific account. Document correlation attributes so operators know how alias, email, or employee number map to the identity you intend to change.

Example — say this to I T D R. We will not wait for H R aggregation. We resolve the identity by alias, resolve Terminated by name on the profile, set lifecycle, then verify with GET. Managed sources should receive disable provisioning from that lifecycle change. Call out any unmanaged source that still needs a direct account disable.

Example — say this about hardcoding Leave of Absence. I Ds are tenant-specific and differ by environment. Resolve by name from the identity profile’s lifecycle states each run. Sandbox GUIDs in a production job are a silent no-op or a wrong-state mutation waiting to happen.

Failure modes. Hardcoding Leave of Absence or Terminated GUIDs. Disabling one account and declaring the identity offboarded. No verify GET — ticket closed on H T T P accepted alone. Racing with aggregation that overwrites an attribute you patched on the account. Using access request to remove access for a compromised leaver.

Failure modes, continued. Bulk J M L jobs without dry-run. Missing before and after evidence in logs. Assuming every source is lifecycle-managed. Confusing Search lag with “identity not found” during an incident.

Screen close. Module six sequence to memorize: resolve identity, resolve lifecycle state by name, set state, verify with GET. Lifecycle for emergency offboard; account disable for unmanaged edges; never wait on the H R file when security needs now.
