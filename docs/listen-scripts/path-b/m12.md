# Module — Transforms

> **Unit ID:** `m12`  
> **Path:** B · Implementation  
> **Source of truth for Listen mode.** Edit paragraphs below; blank lines separate spoken utterances.

---

Module twelve is transforms — attribute mapping without code. Cold open for Identity Security Cloud: if you jump to BeanShell to lowercase an email, you just bought review and install debt that a transform would have avoided. Start at the lightest extension point.

Outcomes: author and read transform JSON shaped with type, attributes, and input; decide transform versus rule with a clear complexity boundary; reference transforms from identity profiles and resolve objects by name when you manage them through A P Is.

A transform is deterministic calculate-and-map during aggregate or provision. Common patterns: concat, lower, upper, substring, date format, firstValid, and lookup. Use them to standardize email, user principal name, and display name across sources.

Mental model of the extensibility ladder you will climb through this track: transforms first, then workflows for event process, then SaaS connectors when you need a Source, then customizers to tweak connector I O, then rules when the vocabulary truly fails, then external A P I jobs for heavy batch. Prefer the lightest fit.

Shape without dumping code: a lower transform wraps an account attribute input from a named source — for example H R source email. A firstValid transform tries preferred name, then legal name, and takes the first non-empty value. Compose small transforms rather than one opaque monster.

You can list and manage transforms through the software development kit — Transforms A P I, list Transforms V one in two point x — aligned with per-service paths. Still never hardcode opaque transform I Ds in runbooks as if they were portable across tenants; resolve by name.

Say this: if firstValid plus lookup plus lower can express it, use a transform. Rules are the exception path. Workflows are for multi-step events with approvals or side effects — not for renaming attributes on aggregate.

When transforms lose: multi-source orchestration with approvals; logic that needs complex loops or external calls beyond the transform vocabulary. Then you escalate to rule, workflow, or an external service — deliberately.

Enterprise craft: naming conventions, sandbox-to-prod promotion, identity profile mapping review, and test identities with before-and-after attribute checks. Editing transforms only in prod is how silent identity corruption ships.

Failure modes: BeanShell for string normalize; transforms that assume source display names differ across tenants with no documentation; dual-maintaining a transform and a rule for the same attribute.
